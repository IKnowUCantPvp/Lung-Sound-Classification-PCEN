## 🛠️ Change Log from Original PCEN Branch

To achieve this 86% target, a massive overhaul of the `src/pyTorchModels.py` and `src/trainPCEN.py` files was required. Here is every major upgrade implemented in the `mr-pcen` branch:

### 1. Data Leakage Fix & Validation Integrity
*   **Previous Issue:** The original script grouped all audio files and split them randomly. Because recordings were simply chunked versions of a single continuous patient interaction, chunks from the *same patient* wound up in both the Train and Temp/Eval splits. The model simply "memorized" the patient's breathing cadence or microphone noise, giving a false 89% Validation Accuracy but a real-world 28% Eval Accuracy.
*   **Change:** Explicitly separated the datasets at the directory level (`data/train` vs `data/test`), ensuring that no patient from the training set ever touches the validation loops.

### 2. Addressing Class Imbalance
*   **Previous Issue:** COPD makes up ~3400 samples, while Lung Fibrosis makes up just ~100 samples. The original model easily collapsed into over-predicting COPD while entirely ignoring rare diseases.
*   **Change:** Implemented a PyTorch `WeightedRandomSampler` inside the `DataLoader`. The sampler mathematically forces every training batch to have an equal probability of showing a rare disease vs. a common disease.
*   **Change:** Swapped `CrossEntropyLoss` for **Focal Loss** (`gamma=2.0`), which actively down-weights the loss generated by "easy" obvious examples and forces the optimizer to focus its gradients on correcting hard mistakes.

### 3. Conv2D Subnetwork Capacity (Scaling Up)
*   **Previous Issue:** The original 5-layer CNN maxed out at only 32 filters, lacking the parameter precision to learn 10 distinct complex lung sounds across 128 Mel-frequency channels.
*   **Change:** Scaled up the convolutional architecture substantially:
    *   Conv1: 16 filters
    *   Conv2: 32 filters
    *   Conv3: 64 filters
    *   Conv4: 128 filters
    *   Conv5: 128 filters
    *   Dense Head: 128 units

### 4. Training Stability via Batch Normalization
*   **Previous Issue:** The deeper the network got, the more it suffered from internal covariate shift, causing extremely chaotic and slow gradient convergence.
*   **Change:** Added `nn.BatchNorm2d` directly subsequent to every `Conv2d` module, and `nn.BatchNorm1d` before the final Dense activation.

### 5. SpecAugment (Regularization)
*   **Previous Issue:** Overfitting to specific static noises unique to the `cleanTrainDataset`.
*   **Change:** Embedded `torchaudio.transforms.FrequencyMasking(15)` and `TimeMasking(35)` directly into the `forward` pass (triggered only during `train` mode). This randomly zeros out chunks of the spectrogram, forcing the model to learn the overarching sound profile rather than isolated pixels. Dropout was also increased to 40%.

### 6. Learning Rate Optimization
*   **Previous Issue:** A static learning rate caused the model to bounce around the local minimum instead of settling precisely.
*   **Change:** Added the PyTorch `ReduceLROnPlateau` scheduler. If the validation accuracy stagnates for 3 epochs, the learning rate is slashed in half, allowing for extremely fine-tuned, tiny gradient steps in the final epochs.

### 7. Custom Trainable PCEN
*   **Previous Issue:** The default `speechbrain` PCEN layer only natively applies `requires_grad=True` to the `alpha` scaling factor, which is mathematically limited in how it handles dynamic background noise over time.
*   **Change:** Rewrote the entire PCEN formulation visually from scratch into a custom `CustomPCEN` PyTorch module:
    *   Locked `alpha` mathematically at **`0.95`**.
    *   Configured the Exponential Moving Average `smooth_coef` to be a pure `nn.Parameter((1, 128))` initialized at `0.025`.
    *   The PyTorch optimizer now trains *how fast* the model should adapt its signal smoothing independently for *every single mel-frequency bin*!
